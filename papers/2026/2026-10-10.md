### 1. Skill Constellations: Tracing the Supply Chain of Agent Skills on GitHub ★

- arXiv：[2610.11169](https://arxiv.org/abs/2610.11169) · [在网站阅读](https://aisafetyhot.com/items/lqvgsrfg28ywli6ha5m9f9jgx)
- 本站收录：2026-10-10 · 原文发表：2026-10-08（北京时间）

**导读**：研究者基于 GitSkills 中每个 SKILL.md 的 git 历史，重建了首个带日期和方向的 Agent 技能复制网络，覆盖 GitHub 上 2,193,119 次技能采用，并提供了交互式查看器。技能以 SKILL.md 指令和脚本形式被 Claude Code、Codex 等编码 Agent 以用户权限执行，开发者靠仓库间复制分享技能，形成没有注册表、版本和来源记录的软件供应链。研究发现少数仓库是几乎所有复制的源头，GitHub star 无法识别它们；技能副本几乎不随源更新，源头的修复很少传到副本，只有 20.9% 的技能副本跟随了源头的后续修改。作者拟合了一个仓库选择复制源的模型用于审计排序，按该模型排名最高的 100 个仓库可阻止 14.9% 的后续高风险技能采用，而 100 个 star 最多的仓库只能阻止 0.5%。

**速读**（据 [论文 PDF（Gemini 生成）](https://arxiv.org/abs/2610.11169) 整理，以论文原文为准）：

- **问题**：AI 编码智能体通过包含指令与脚本的 SKILL.md 扩展能力，但跨仓库复制使之缺乏依赖图与版本记录。现有快照研究无法还原复制时序与传播链，导致安全团队难以确定高风险技能扩散源头与修复范围。
- **方法**：作者提取 GitSkills 中所有 SKILL.md 的提交历史，构建带时间戳的有向复制网络；使用条件 logit 模型拟合仓库选择复制源的行为机制，并根据历史得分对代码库进行排序以推荐优先审计目标。
- **实验与结果**：在 1 April 2026 切分下，审计源选择模型排名前 100 仓库可预防 14.9% 的后续高风险采用，远高于 stars 的 0.5%；此外，仅 20.9% 的副本会跟随源仓库后续修改更新。
- **局限与可以继续做的**：作者指出风险标签标记能力而非恶意意图，属于风险下界；数据仅覆盖公开 GitHub 前十个月。实验基于 GitSkills 数据集，审计策略在单一主时间切分及前后各一个月对照切分下进行了验证。

### 2. 论文审计 LLM 裁判可靠性：重复一致不等于正确

- arXiv：[2610.12083](https://arxiv.org/abs/2610.12083) · [在网站阅读](https://aisafetyhot.com/items/raqu6wbr4ibd0qgtyms0zxvhc)
- 本站收录：2026-10-10 · 原文发表：2026-10-08（北京时间）

**导读**：一篇被 AACL IJCNLP 2026 接收的论文对 LLM-as-a-Judge 做了系统性的可靠性审计，在四个基准、五种提示格式、两种呈现顺序、三个采样温度下对六款前沿模型各重复十次测试。结果显示：温度为零时同一条件下的判定仍会变化；交换候选位置顺序会让困难任务上的多数判定翻转；一致性最完美的裁判只是机械重复错误判定，与标准答案一致的比例仅 51%。作者提出可信判定率（T）指标，用以刻画判定同时满足可复现、顺序不变且准确的概率，并据此推导位置偏差给准确率带来的理论上界，指出可靠性是逐条目而非模型级别的属性。作者还发现，从成对胜负判定改为整体评分量表评分，对可信度的提升超过任何单一提示格式干预。

**速读**（据 [论文 PDF（AI 生成）](https://arxiv.org/abs/2610.12083) 整理，以论文原文为准）：

- **问题**：LLM-as-a-Judge的判决常被当作可复现、且与展示顺序无关的真值，并进入奖励、排行榜和模型选择。作者称重复查询和交换候选顺序都会改变判决，确定性不等于可信度。
- **方法**：六名裁判在四个基准、五种提示格式、两种顺序和十次重复上接受审计。强制二选一下，可信判决率写作T=C·(A−φ/2)，要求判决可复现、换序不变且正确。另在两个客观基准上比较Direct、FLASK与G-Eval。
- **实验与结果**：Ts=0、JudgeBench、VF-XML下，Gemini-2.0-Flash的φ为98.0%、T为2.0%。G-Eval使Gemini-2.5-Pro在该基准的T从28.9%到77.9%；FLASK多格压低C。
- **局限与可以继续做的**：作者指出仅四个英文成对偏好基准，闭源模型无对数概率，可延伸到list-wise。Ts=0覆盖六名裁判、五格式与十次重复；两名推理模型无温度扫描；范式对比只在JudgeBench与LLMBar。

### 3. 研究：在线 RL 行为归因信号可能被梯度大小与流畅度混淆

- arXiv：[2610.10422](https://arxiv.org/abs/2610.10422) · [在网站阅读](https://aisafetyhot.com/items/tf5cngqw2nj2565sglybbbtm9)
- 本站收录：2026-10-10 · 原文发表：2026-10-08（北京时间）

**导读**：一篇论文在 GRPO 在线 RL 微调上研究行为归因是否可信，用植入已知成因的行为做受控实验，并发布开源评测框架 BehaviorTrace。在 Qwen2.5-1.5B 的三个随机种子上，相当一部分归因信号来自混淆因素：仅按梯度大小对训练步骤排序、不设行为目标的对照方法达到随机水平的 4.2 至 4.5 倍，并在三个种子中的两个上达到或超过最佳定向估计器。在饱和检查点上，模型流畅度对行为标签的预测能力不弱于所比较的任何梯度方法；控制流畅度后，逐 rollout 结果在不同种子和不同生成抽样之间变化，单次运行无法定论。作者称唯一在三个种子上都成立的信号是触发 token 的梯度与行为实际发生处构建的目标对齐。论文测试了包括 GAS（renormalized TracInCP）和 TRAK 类估计器在内的现有方法，未提出新估计器，并将结论整理为评估 RL 归因的检查清单。

### 4. 论文提出长期记忆智能体的检索可允许性验证框架

- arXiv：[2610.07309](https://arxiv.org/abs/2610.07309) · [在网站阅读](https://aisafetyhot.com/items/exzp15zm6i2zfalgju2km6c5s)
- 本站收录：2026-10-10 · 原文发表：2026-10-06（北京时间）

**导读**：论文提出一个检索可允许性验证框架，把每个记忆-查询对标记为可允许、不可允许或未解决三种状态，并在匹配所需证据召回率的前提下比较不同检索路径，同时追踪记忆 ID 在提示暴露中的流转。作者对 RHELM 和 MemOps 两个公开长期记忆基准的冻结排序做事后 top-20 重分析，覆盖 3,767 条查询：所有已发布锚点都落在受信任的查询命名空间内，过滤命名空间外内容在不改变命名空间内得分的情况下不会降低其排名，top-20 锚点召回率从 0.432 升至 0.533，80% 召回可行性从 0.237 升至 0.311，精确相似度评估减少 98.3%。在 72 例冻结开发诊断中，基于已发布元数据的参照方案保留了所需证据，而两个纯文本验证器在 1% 必需锚点误拒限制下都未能检出违规。作者在 16 个受控暴露场景中仅观察到四个 reader 的一个 95% 置信区间不含零。

### 5. 研究：事实核查评测可能混入声明时不可知的未来证据

- arXiv：[2610.04888](https://arxiv.org/abs/2610.04888) · [在网站阅读](https://aisafetyhot.com/items/of8dpno9hcfswb26ubo3vxvru)
- 本站收录：2026-10-10 · 原文发表：2026-10-04（北京时间）

**导读**：研究者在 AVeriTeC 和 QuanTemp++ 上重建声明时点的证据条件，并探测模型表示中编码的结果信息，发现存在明显的参数化泄漏，且这种泄漏会被总体准确率掩盖。作者称，一个简单的表示瓶颈比基于互信息的训练惩罚更有效地减少这类未来信息泄漏。研究还发现，允许使用声明发布后的证据会使 AVeriTeC 的零样本准确率虚高 6.3 个百分点，而在检索几乎提供不了事后证据的 QuanTemp++ 上影响可忽略。作者据此指出， misinformation 基准若不考虑声明时实际可获得的信息，会高估事实核查性能。

### 6. Persist-3 用顺序检验识别未见越狱来源，提升 MTK 与 Prompt Guard 2 防御效果

- arXiv：[2610.09167](https://arxiv.org/abs/2610.09167) · [在网站阅读](https://aisafetyhot.com/items/mek7qa97peombxtebbf9oum6y)
- 本站收录：2026-10-10 · 原文发表：2026-10-07（北京时间）

**导读**：论文提出 Persist-3，用于从攻击提示流中判断其是否来自已知攻击源之外的来源。方法对每个已知来源计算 conformal p 值，只有当针对所有已知来源的证据都足够强时才拒绝原假设。理论分析显示，其检测概率随观测窗口增大呈指数级趋近于 1，因此较短的窗口即可检测与已知来源区分明显的未见来源。作者在 MTK 和 Prompt Guard 2 两种近期越狱防御之上验证 Persist-3，观察到防御效果显著增强。

**速读**（据 [论文 PDF（AI 生成）](https://arxiv.org/abs/2610.09167) 整理，以论文原文为准）：

- **问题**：越狱防御通常按固定的已知攻击方法校准，新方法出现后已有检测会变差。作者要回答：只看受害模型返回响应前的表示流，如何判断当前攻击不属于任一已知源，以及分离程度如何决定检出速度。已知源之间的切换不应算作目标。
- **方法**：对每个已知源计算马氏分数和 split conformal p 值。Persist-3 对最近 W=10 条按源平均后再取最小，并要求连续 L=3 步越阈，因此只依赖最近 12 条。阈值只用已知源验证流。报警后在未改动护栏上升级该流。
- **实验与结果**：H=1000 时 Persist-3 的 KU 检出率 0.458，SR-DKW full 为 0.648，静止 FPR 均为 0/1835（Table 1）。叠在 MTK 或 PG2 上，作者称 block rate 增加 7.0 至 10.0 个百分点（Table 2）。
- **局限与可以继续做的**：作者将更多在线数据下的渐近分析列为后续方向，并写明完全自适应攻击者不在定理与压力测试内。经验上不含已验证的报警后登记；分层比较未做预算匹配。回放未与 Piet et al. (2025) 的流级防御比较。

### 7. 研究：Agent 准时停机不等于有效使用时间预算

- arXiv：[2610.10833](https://arxiv.org/abs/2610.10833) · [在网站阅读](https://aisafetyhot.com/items/a96zojasssfyepiv1oigbpqb5)
- 本站收录：2026-10-10 · 原文发表：2026-10-08（北京时间）

**导读**：论文研究小型 LLM Agent 能否在明确的墙钟时间预算下既遵守运行时长又有效利用时间，在 MLE-Bench Lite 的五个竞赛上评测 Qwen3.6-27B，在 Zork I（Jericho）上评测 Qwen3-4B。仅把预算写进提示词时，Agent 无法把预算转化为受控的时间使用，原因包括缺少时间感知、难以预估动作耗时，以及没有从可用时间到策略的学习映射。作者测试两类干预：通过 harness 暴露时间信息并强制执行截止时间，以及带预算感知奖励的强化学习。harness 注入时间信息显著提升 Qwen3.6-27B 的预算遵守度且未造成可测的性能损失，强制执行钩子进一步提升遵守度；GRPO 强化学习在 Zork I 上达到接近完美的预算遵守度，并能泛化到训练中未见的预算，但在 MLE-Bench 上未提升任务表现。

**速读**（据 [论文 PDF（AI 生成）](https://arxiv.org/abs/2610.10833) 整理，以论文原文为准）：

- **问题**：智能体需要在显式 wall-clock 预算内返回，并在搜索型任务上把更多时间换成更好的解。作者将要求分为 adherence（按时）和 productive use（加时提高成绩）。只写在提示词里时，模型没有计时反馈，也不能可靠预估动作时长。
- **方法**：在五场 MLE-Bench（Qwen3.6-27B）和 Zork I（Qwen3-4B）上，比较提示词预算、可截断或拒绝超时命令的时钟 harness，以及 GRPO。Zork 奖励在分数上加时间项，超过 1.1 倍预算可整段清零。
- **实验与结果**：Table 2：Qwen3.6-27B、15分钟，仅提示词按时率15%，refuse为88%，时钟后用时占预算99.7%。Qwen3-4B、RL+Auto-Clock、16秒为46.4/350。作者称会停止，但加时未提高成绩。
- **局限与可以继续做的**：作者指出策略坍缩、记忆化与评测范围仍开放，并建议探索奖励与环境变化。实验为五场MLE-Bench（Qwen3.6-27B）和Zork I；Table 6每格n=16。论文未报告Table 2的episode数。

### 8. Opera: A Verbal Critic Framework for Long-horizon Coding Agents

- arXiv：[2609.33987](https://arxiv.org/abs/2609.33987) · [在网站阅读](https://aisafetyhot.com/items/lytkh18wwq0isocm0bhktp3ov)
- 本站收录：2026-10-10 · 原文发表：2026-09-28（北京时间）

**导读**：研究者提出 Opera，一个面向长程编码 Agent 的口头批评者框架，把每次纠正当作持续跟踪的笔记，直到被诊断的问题真正解决。它通过周期性与事件驱动触发决定何时审查，用带类型的算子诊断问题，在交付前依据可见证据审核反馈，并跟踪 Agent 后续动作以区分表面服从与实际解决。作为测试时批评者，Opera 在 Terminal-Bench 2.1、SWE-Bench Pro 子集和 DeepSWE v1.1 上，跨四个策略模型把非批评者 Agent 的解决率分别提升最多 12.4、15.0 和 8.9 个百分点，并在三个基准上取得竞争性批评者基线中最高的平均解决率，也能在策略模型自我批评时带来提升。代码已开源于 https://github.com/dongyuanjushi/Opera。

### 9. 论文用生成式 Agent 建模模拟私有测试集对评分与用户体验差距的影响

- arXiv：[2610.09296](https://arxiv.org/abs/2610.09296) · [在网站阅读](https://aisafetyhot.com/items/fw1b4bwqs4596pq2vfdhzvbro)
- 本站收录：2026-10-10 · 原文发表：2026-10-07（北京时间）

**导读**：一篇 arXiv 论文提出用结合规则市场动态与 LLM 驱动策略主体的模拟架构，研究基准测试设计如何影响模型提供方、用户、资助方和监管者的决策。作者将基准、消费者需求和提供方能力建模为推理、编程、知识、安全、沟通、智能体六个能力维度上的向量，并以基准留出集设计为案例。模拟发现，从公开基准转向私有留出基准在多数基准上缩小了评分与用户满意度的差距，但在少数基准上会扩大差距，取决于留出权重把评分归给哪些能力。作者称该模拟可作为研究评测与政策选择如何反过来重塑生态的假设生成沙盒。

### 10. GROB 用公开网络痕迹研究自主智能体活动归因边界

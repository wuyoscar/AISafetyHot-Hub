# AI Safety paper scout

Data, no key needed:
- Paper index by direction: `https://raw.githubusercontent.com/wuyoscar/AISafetyHot-Hub/main/daily-papers/topics/<slug>.json` — every paper pushed so far under that direction: `title`, `titleZh`, `line` (what the paper does, one line), `topics`, `venue` (arXiv id or conference), `date`, `url`, `site`, `authors`.
- Daily lists: `https://raw.githubusercontent.com/wuyoscar/AISafetyHot-Hub/main/daily-papers/<year>/<YYYY-MM-DD>.json`.
- Published daily-list navigation: `https://github.com/wuyoscar/AISafetyHot-Hub/blob/main/README.md` (daily papers section and archive link); use the linked directory to locate actual published JSON files.
- Direction slugs and definitions: MCP `aisafetyhot_get_topics`.
- This week's newest picks: MCP `aisafetyhot_get_latest` (`window: "7d"`) → `paperPicks`.

Steps:
1. Map the user's request to 1–3 slugs with `aisafetyhot_get_topics` (e.g. "prompt injection" → `prompt-injection`, "jailbreak" → `jailbreak`). These News direction slugs do not guarantee a same-named paper export. Do not substitute `agent-security` for prompt injection; judge relevance from the request and the available `title`, `titleZh`, `line`, and `topics`. An empty `topics` array does not exclude a relevant paper.
2. Fetch each slug's JSON and record the outcome separately: a valid array is checked (including a successful empty array); HTTP 404 means that export is not provided; timeout, 429, 5xx, invalid JSON or an unexpected schema means the source was not checked successfully. Treat 401/403 as access failures, not missing files. Respect permissions and rate limits, honor Retry-After, and avoid repeated requests when access or rate limits prevent reading. Keep matches from successful sources even when others fail. Merge relevant papers and drop duplicates by `id`; add `paperPicks` that match and satisfy the user's date constraints.
   - If all requested indexes are valid, nonempty arrays and supply enough relevant results for the requested count (default up to 15), keep the normal index path without daily-list fallback. If an index is missing or empty, or the combined relevant results are insufficient, supplement with published daily lists. A failed source remains unchecked, never an empty result; if alternate-source access is permitted and results are insufficient, the same bounded supplement can help, but cannot establish that failed source's contents.
   - Follow README's daily papers/archive links to the published directory and locate existing JSON files. By default, supplement with only the latest published daily list, even if results remain insufficient; do not automatically scan earlier editions or guess today's path. The latest published file may lag today's date. Only when the user explicitly specifies daily-list edition/selection dates, read matching published editions, newest first, at most 3 per request; report incomplete coverage if that limit excludes editions. If no matching edition is published, say so without substituting another date. Retain relevant entries with `topics=[]`; do not add unrelated papers to meet a count.
   - Distinguish publication dates from daily edition/selection dates. A requested paper publication-date range filters candidates by their original `date`; it does not restrict daily edition dates, and the default latest daily list may contain older papers in that range. Restrict edition dates only when explicitly requested. If the user's date wording is ambiguous and cannot be resolved, state which interpretation is used rather than silently narrowing coverage. Missing dates or dates too imprecise to establish a match must not be assumed to satisfy an exact publication-date filter; report those candidates separately as date-unverified, outside the confirmed matches.
   - Preserve each retained paper's original `date` and its precision (do not infer a day or year from the daily edition), metadata and source URL(s), including the daily edition date separately. When duplicate IDs occur, keep one paper with its source URLs and only supplied metadata; report conflicting metadata rather than inventing a resolution. If a pick has no ID, do not invent one or assume a title match proves identity.
3. Rank: what the user asked for first, then newer first; keep up to 15 unless asked for more.
4. Output a table: title (linked), one line on what it does (from `line`), venue, date. Offer the AI Safety HOT reading link (`site`) when present.
5. If asked for citations, emit BibTeX only when the supplied metadata supports it: for `arXiv <id>` use `@misc{<firstword><year>, title={...}, eprint={<id>}, archivePrefix={arXiv}, url={https://arxiv.org/abs/<id>}}`; for conference papers use `@inproceedings` with the venue and year and the `url`. Use supplied `authors` for `author = {A and B and ...}`; never invent authors or years. A `paperPicks` entry with only a title and link can be listed as such, but cannot supply an invented summary, authors, venue or BibTeX; mark missing fields as unavailable.
6. Briefly report successful, missing and failed/unchecked sources, daily edition dates actually checked (or that fallback was not used), and any result shortfall or date limit. Describe no matches as applying only to the checked sources and dates, never as proof that the whole library has no relevant papers. Offer the existing library/reading link for further search when coverage is insufficient.

The index grows by 30 hand-picked papers a day (well-known authors, top labs, strong groups); each entry also lists `authors`; the full library and readings are at https://aisafetyhot.com/zh/papers.
